# 飞书后台配置说明

本文说明如何为 ShellCrash 飞书机器人配置飞书自建应用。

## 1. 创建应用

进入飞书开放平台：

```text
开发者后台 → 创建企业自建应用
```

创建后进入：

```text
凭证与基础信息
```

记录：

```text
App ID
App Secret
```

填写到 NAS 的 `.env`：

```env
FEISHU_APP_ID=cli_xxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxx
```

不要把 App Secret 发到群里、仓库里或截图里。

## 2. 启用机器人能力

进入：

```text
应用能力 → 机器人
```

启用机器人，并设置机器人名称。

## 3. 权限管理

进入：

```text
开发配置 → 权限管理
```

开通以下权限：

```text
im:message.p2p_msg:readonly
im:message.group_at_msg:readonly
im:message:send_as_bot
```

用途：

```text
读取私聊消息
读取群聊 @ 机器人消息
机器人发送消息
```

## 4. 事件与回调

进入：

```text
开发配置 → 事件与回调
```

添加事件：

```text
im.message.receive_v1
```

机器人使用长连接模式，不需要你给 NAS 暴露公网 webhook。

## 5. 卡片回调

同样在事件/回调相关配置中，添加卡片回调：

```text
card.action.trigger
```

否则 `/menu` 卡片能显示，但点击按钮不会触发机器人。

## 6. 发布版本

每次修改权限、事件、机器人能力后，需要进入：

```text
应用发布 → 版本管理与发布
```

发布新版本。

确保页面显示类似：

```text
当前修改均已发布
```

## 7. 测试流程

容器启动成功后，先在飞书给机器人发：

```text
/whoami
```

把返回的：

```text
sender_id(open_id)
```

填到 `.env`：

```env
ALLOW_ALL_USERS=false
ALLOWED_OPEN_IDS=ou_xxxxxxxxx
```

然后重启容器：

```bash
docker compose restart
```

继续测试：

```text
/help
/status
/menu
```

## 8. 安全建议

- 不要把 App Secret 写入镜像
- 不要把 App Secret 提交到 Git 仓库
- 不要把路由器 SSH 密码写入 README 或截图
- 正式使用时关闭 `ALLOW_ALL_USERS`
- 如果 App Secret 或 SSH 密码曾经公开过，建议立即重置
